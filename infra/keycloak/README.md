# Області Keycloak

Keycloak запускається службою `idp` файлу `compose.yaml` з параметром `--import-realm` і під час старту імпортує обидва файли цієї теки. Перевірка готовності контейнера стає успішною лише після завершення імпорту.

| Файл | Область | Призначення |
|---|---|---|
| `app-realm.json` | `app` | Область застосунку: ролі, клієнти, тестові користувачі |
| `foreign-realm.json` | `foreign` | Інший видавець токенів для негативної перевірки N2. Під свою предметну область не змінюється |

## Що в області `app`

**Ролі.** `operator` і `customer`. Роль потрапляє в токен заявою `roles` (відображувач `app-realm-roles`).

**Власник.** Атрибут користувача `owner_id` описано в профілі користувача області (блок `components`, `kc.user.profile.config`), тому його видно в консолі адміністратора на вкладці атрибутів користувача. Відображувач `owner-id` переносить його в заяву `owner_id` токена.

**Аудиторія.** Відображувач `app-audience` додає в заяву `aud` значення `app-api`, яке перевіряє застосунок (`Auth:Audience` у `appsettings.json`).

**Клієнти.**

| Клієнт | Потік | Строк токена | Призначення |
|---|---|---|---|
| `app-web` | код авторизації з PKCE | 300 с | вебклієнт |
| `app-test` | паролі | 3600 с | скрипти і самоперевірка |
| `app-expiring` | паролі | 60 с | прострочений токен, перевірка N1 |
| `app-other` | паролі | 3600 с | токен для іншої аудиторії, перевірка N3 |

Потік паролів дозволено лише тестовим клієнтам, бо скрипти отримують токен без браузера.

**Користувачі.** `operator1` з роллю `operator` і `customer1` з роллю `customer` і атрибутом `owner_id` = `cus-2`. Пароль кожного збігається з іменем. Самоперевірка і скрипти читають паролі зі змінних середовища `SELFCHECK_OPERATOR_PASSWORD` і `SELFCHECK_CUSTOMER_PASSWORD`.

## Що змінити під свою предметну область

1. Назви ролей у `roles.realm` і в `realmRoles` користувачів.
2. Значення `owner_id` у користувачів, щоб вони збігалися з ідентифікаторами власників у початкових даних застосунку.
3. Значення аудиторії у відображувачі `app-audience`, якщо його змінено в `appsettings.json`.

Після зміни файла Keycloak перечитує область, коли контейнер створюється заново.

```powershell
docker compose --profile idp up -d --force-recreate --wait idp
```

## Як перевірити імпорт

Токен для `customer1` отримується тестовим клієнтом. Заява `owner_id` має містити значення атрибута.

```powershell
$t = (Invoke-RestMethod -Method Post -Uri http://localhost:15300/realms/app/protocol/openid-connect/token -Body @{ grant_type = 'password'; client_id = 'app-test'; username = 'customer1'; password = 'customer1' }).access_token
```

Консоль адміністратора відкривається за адресою `http://localhost:15300`, ім'я і пароль задано змінними `APP_IDP_ADMIN` і `APP_IDP_ADMIN_PASSWORD` у файлі `.env`.
