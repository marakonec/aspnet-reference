# Паспорт предметної області еталона «Прокат вимірювальних приладів»

Рядки паспорта ті самі, що в каталозі предметних областей `docs/DOMAINS.md`. Бланк для власної предметної області лежить у `docs/templates/DOMAIN.md`.

**Сутності**

- `InstrumentModel` (модель приладу) — назва, кількість екземплярів усього і вільних
- `Instrument` (екземпляр) — модель, серійний номер
- `Customer` (замовник) — назва, контактний телефон
- `Reservation` (бронювання) — замовник, стан, примітка
- `ReservationItem` (позиція бронювання) — модель, кількість
- `IssueRecord` (запис видачі) — бронювання, час, хто видав

| Рядок паспорта | Значення |
|---|---|
| «Один до багатьох» | `InstrumentModel` → `Instrument` |
| «Багато до багатьох» | `Reservation` ↔ `InstrumentModel` через `ReservationItem` |
| Ключова операція | `POST /reservations/{id}/issue`, видати прилади за бронюванням |
| Що змінюється в одній транзакції | стан `Reservation` → `Issued`, `InstrumentModel.AvailableCount` зменшується на замовлену кількість, новий `IssueRecord` |
| Сценарій конкурентності | двоє операторів одночасно видають останній вільний генератор сигналів (`mdl-gen`, усього один екземпляр), обидва бачать «вільно» |
| Ідемпотентна операція | `PUT /reservations/{id}/notes` |
| Неідемпотентна | видача, бо повторний виклик є другою видачею |
| Ролі | `operator` видає прилади за будь-яким бронюванням, `customer` бачить і створює лише власні бронювання |
| Що означає «своє» | `Reservation.CustomerId` збігається з ідентифікатором власника в токені |
| Кешований ресурс | `GET /models`, каталог моделей |
| Некешований | `GET /models/{id}/availability`, кількість вільних екземплярів |
| Навантаження на читання | каталог моделей читають усі екрани бронювання, а змінюється він раз на семестр |
| Зовнішня залежність | сповіщення замовника про видачу (у репозиторії заглушка `src/App.Notifier`) |
| Чутливий атрибут | `Customer.Phone` |
| Сутність зі станом | `Reservation`: `Draft → Reserved → Issued → Returned / Cancelled` |
