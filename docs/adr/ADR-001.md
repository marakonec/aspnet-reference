# ADR-001. Межі застосунку і спосіб організації коду

**Статус:** ухвалено. **Дата:** 13.09.2026. **Тег:** stage-1-v2026.

## Контекст

Сервіс прокату вимірювальних приладів. Один процес, одна команда розробників, один споживач API на старті. Ключова операція змінює три сутності і має бути атомарною. Код має прожити кілька змін мажорної версії платформи.

## Рішення

Модульний моноліт з явними межами. За межу застосунку винесено чотири речі: конфігурацію, сховище, постачальника ідентичності і телеметрію. Кінцеві точки описано в стилі Minimal API.

## Розглянуті альтернативи

| Альтернатива | Причина відхилення |
|---|---|
| Кілька сервісів від початку | Ключова операція змінює три сутності. Поза межею одного процесу локальна транзакція вже не допомагає, і доводиться платити вихідною скринькою та ідемпотентним споживачем ще до того, як з'явиться навантаження, яке це виправдовує |
| Контролери як основний стиль | Для нових проєктів документація платформи рекомендує Minimal API. Причин обрати контролери (розширення прив'язки моделі, OData) у цій предметній області немає |

## Наслідки

Кожна винесена межа додає шар непрямості і ще одне місце, де можна помилитися в налаштуваннях. Для конфігурації треба знати порядок джерел, для телеметрії адресу приймача.

## Стратегія версіонування

Номер версії API живе в адресі документа контракту (`/openapi/v1.json`). Без нового номера дозволено додавати необов'язкові поля відповіді, нові кінцеві точки і нові необов'язкові параметри. Новий номер потрібен, коли поле вилучається або перейменовується, коли необов'язкове поле запиту стає обов'язковим і коли змінюється тип або формат поля.

## Чим підтверджено

| Твердження | Метод перевірки | Результат | Висновок |
|---|---|---|---|
| Документ контракту відповідає правилам курсу | `docker compose run --rm spectral` | помилок рівня error немає | контракт придатний для збереження |
| Неправильне тіло відхиляється на межі | самоперевірка, перевірка 1.3 | 400 у форматі опису проблеми з переліком полів | валідація працює до обробника |
| Додавання необов'язкового поля сумісне | `docker compose run --rm oasdiff` після зміни | несумісних змін немає | зміна не потребує нового номера |
| Перейменування поля несумісне | `docker compose run --rm oasdiff` після зміни | названо вилучене поле | зміна потребує нового номера |
